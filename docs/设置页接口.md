# 设置页接口说明

> 给做设置界面的人（目前 UI 归 E）。这一页只需要调下面这些接口，**不用碰输入/音频/存储的内部实现**。
>
> 相关代码：`core/InputActions.ts`、`core/InputSystem.ts`、`core/GameSettings.ts`、`audio/AudioManager.ts`

## 一句话总览

| 要做的控件 | 调什么 | 谁负责持久化 |
|---|---|---|
| 音量滑条（主音量 / 音乐 / 音效） | `audioManager.setChannelVolume(...)` | 自动 |
| 键位列表 + 重映射 | `inputSystem.getBindings(...)` / `inputSystem.rebind(...)` | 自动 |
| 恢复默认 | `audioManager.setChannelVolume` / `inputSystem.resetBindings()` | 自动 |
| 想跟着设置变化刷新 UI | `eventBus.on('settings-changed', ...)` | — |

**所有写入都会自动落盘**（localStorage），界面不需要自己存。

---

## 1. 音量

```ts
import { audioManager } from '../audio/AudioManager';

audioManager.setMasterVolume(0.8);        // 主音量，0~1
audioManager.setChannelVolume('bgm', 0.6); // 音乐
audioManager.setChannelVolume('sfx', 0.9); // 音效

audioManager.getMasterVolume();            // 读回来给滑条定位
audioManager.getChannelVolume('bgm');
audioManager.getEffectiveVolume('bgm');    // 实际生效值 = master × bgm
```

- 三个分组：`'master'` / `'bgm'` / `'sfx'`，取值都是 `0~1`，超范围会被夹住。
- 默认值：master 0.8、bgm 0.7、sfx 0.8。
- 滑条直接用 `getXxxVolume()` 初始化，`onValueChanged` 里调 `setXxxVolume()` 即可，**不需要去抖也不需要手动保存**。

> ⚠️ **现在拖动滑条听不到任何变化** —— 项目里还没有音频素材，`AudioManager` 的播放部分是空实现。
> 音量这条链路本身是真的（能存、能读、能算），等音频素材接入后自动生效，届时界面不用改。

## 2. 键位

```ts
import { inputSystem } from '../core/InputSystem';
import { ALL_ACTIONS, ACTION_LABELS, bindingLabel, key } from '../core/InputActions';
import { KeyCode } from 'cc';

// ① 列出一行（做列表用）
for (const action of ALL_ACTIONS) {
    const title = ACTION_LABELS[action];                        // 「跳　跃」
    const keys  = inputSystem.getBindings(action).map(bindingLabel);  // ['空格']
}

// ② 改一条绑定（index 见上，越界返回 false）
inputSystem.rebind(action, 0, key(KeyCode.KEY_K));
inputSystem.rebind(action, 1, { kind: 'key', key: KeyCode.KEY_L });

// ③ 单行 / 全部恢复默认
inputSystem.rebind(action, 0, DEFAULT_BINDINGS[action][0]);
inputSystem.resetBindings();
```

- `ACTION_LABELS` 是动作的中文名，**别在 UI 里再手写一份**，否则改动作名会两边不同步。
- `bindingLabel(b)` 把绑定转成可读文本（`空格` / `回车` / `D` / `↑`…）。
- `DEFAULT_BINDINGS` 是出厂绑定表，做「单行恢复默认」时读它。
- 改完会立即生效并落盘，**不需要重启或重载**。

### 做重映射 UI 时必须注意

捕获「玩家按下的下一个键」时，**动作层同时也是活的** —— 玩家为了把「跳跃」改成 K，按下 K 的那一刻会同时触发「踏云闪」。

下一轮实现重映射时要先给 `InputSystem` 加一个**捕获模式**（进入捕获时挂起动作解析，退出时恢复），例如：

```ts
inputSystem.setCaptureMode(true);   // 待实现
// ... 监听 input.on(Input.EventType.KEY_DOWN) 拿第一个键 ...
inputSystem.setCaptureMode(false);
```

`InputSystem.onKeyDown` 里加一句「捕获模式下不写状态」即可，改动很小。**别绕过它直接在 UI 里读原始按键**，否则这个坑一定会踩。

## 3. 数据与持久化

- 存档键：localStorage 的 `yunxiu.settings`，内容是一段 JSON。
- 结构：`{ version, audio: {master,bgm,sfx}, bindings }`；`bindings` **只存被改过的动作**，没改过的读的时候回落到 `DEFAULT_BINDINGS`（这样以后调默认键位，老玩家不会被旧默认值钉死）。
- 读盘全程有保护：JSON 坏了 / 字段缺失 / 版本比代码新 → 回落默认值并打 warn，**不会因为一份坏存档卡死游戏**。
- ⚠️ **`sys.localStorage` 目前只在 Web 端有实现**。打包成原生 App 后设置不会持久化（存储后端已抽成一层，原生分支留了 TODO 要接 `native.fileUtils`）。

## 4. 想知道设置什么时候变了

```ts
import { eventBus } from '../core/EventBus';
import { SettingsChangedEvent } from '../core/GameSettings';

eventBus.on<SettingsChangedEvent>('settings-changed', (e) => {
    if (e.audio) { /* 刷新音量滑条 */ }
    if (e.bindings) { /* 刷新键位列表 */ }
});
```

> 回调必须是**箭头函数属性**（`private onXxx = (e) => {...}`）或显式 bind —— `EventBus` 不传 target，普通方法里的 `this` 会是 `undefined`。

## 现在还没有的东西

| 缺什么 | 状态 | 接的时候注意 |
|---|---|---|
| 音频播放 | `playBgm` / `playSfx` 是空实现 | 用 `getEffectiveVolume()` 而不是分组值直接当 `volume` |
| 键位捕获模式 | 未实现 | 见第 2 节，**做重映射前必须先加** |
| 手柄 / 触屏 | `Binding` 类型留了口子，解析分支未实现 | 手柄的 `held` 建议走轮询（部分平台只在变化时发事件，长按会失真） |
| 分辨率 / 画质等其它设置项 | 未设计 | 加字段到 `GameSettingsData` 并 +1 `version` |
